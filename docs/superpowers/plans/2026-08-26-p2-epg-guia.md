# P2 — Guía de programación (EPG) — Plan de implementación

> **Para trabajadores agénticos:** SUB-SKILL REQUERIDA: usa superpowers:subagent-driven-development para ejecutar este plan tarea a tarea. Los pasos usan checkbox (`- [ ]`).

**Goal:** ahora/después por canal en tarjeta y overlay, tomando la guía del `url-tvg` que cada fuente declara en su cabecera M3U, con degradación honesta donde no hay datos.

**Architecture:** sigue la espina dorsal existente (Go parsea/almacena → API → cliente Svelte). Se captura `url-tvg` en el parse del M3U, se guarda en `providers.tvg_url`, un adapter descarga+parsea el XMLTV a una tabla `epg_programmes` (ventana rodante por `provider_id`), el Syncer refresca por fuente, dos endpoints nuevos sirven ahora/después, y el cliente lo pinta. Aditivo: `mobile/` y el contrato Flutter intactos.

**Tech Stack:** Go 1.26 (encoding/xml streaming, compress/gzip, modernc/sqlite), Svelte 5 + TS, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-26-p2-epg-guia-design.md` (autoridad).

### Task 4: Adapter de descarga + parseo XMLTV

**Files:**
- Create: `internal/adapters/epg/xmltv.go` (parser puro en streaming), `internal/adapters/epg/xmltv_test.go`
- Create: `internal/adapters/epg/fetcher.go` (fetch HTTP con gzip + cap) + test
- Fixtures: `internal/adapters/epg/testdata/*.xml`, `*.xml.gz`

**Interfaces:**
- Consumes: nada de tareas previas.
- Produces:
  - `epg.ParsearXMLTV(r io.Reader, maxBytes int64) ([]domain.Programa, error)` — streaming (`xml.Decoder.Token`), tolerante: una entrada malformada se descarta (no tumba el parse), respeta `maxBytes` (`io.LimitReader`).
  - `epg.Fetcher.Descargar(ctx, url string) (io.ReadCloser, error)` — HTTP guardado (mismo cliente/guardas SSRF que el M3U), descomprime gzip si el cuerpo o la URL lo indican.

- [ ] **Step 1 (test parser):** fixture XMLTV con `<programme start="20260826200000 +0000" stop="20260826210000 +0000" channel="cnn.us"><title>The Lead</title>…`. `ParsearXMLTV` devuelve `Programa{ChannelID:"cnn.us", InicioUTC:<epoch de 20:00Z>, FinUTC:<21:00Z>, Titulo:"The Lead"}`. Casos: offset distinto de UTC (p. ej. `+0200` → epoch correcto), `.xml.gz` (vía Fetcher en su propio test), entrada sin `stop` o con fecha ilegible (se descarta esa, las demás siguen), cap de tamaño (entrada > maxBytes → error de tope). Correr → falla.
- [ ] **Step 2:** implementar `ParsearXMLTV` con `encoding/xml` en streaming (acumular por `<programme>`, parsear `start`/`stop` con `time.Parse("20060102150405 -0700", …)` → `.UTC().Unix()`).
- [ ] **Step 3 (test fetcher):** servidor httptest que sirve `.xml` y `.xml.gz`; `Descargar` devuelve un reader con el XML plano en ambos casos; respeta el cap; una URL no-loopback/no-permitida se rechaza igual que el proxy/M3U.
- [ ] **Step 4:** implementar `Fetcher` reutilizando el patrón del cliente HTTP guardado del provider (no duplicar la guarda SSRF; compartir o replicar el mismo `net.Dialer.Control`/timeouts).
- [ ] **Step 5:** gates verdes. Commit `feat(epg): descarga (gzip, cap) y parseo XMLTV en streaming`.

### Task 5: Integración en el Syncer (refresco por fuente, cadencia, éxito parcial)

**Files:**
- Modify: `internal/services/syncer.go` + `syncer_test.go`

**Interfaces:**
- Consumes: `Provider.TvgURLs()` (T1), `SourceRepository.SetTvgURL` + lectura de `tvg_url` (T2), `EPGRepository.ReemplazarVentana`/`Podar` (T3), `epg.Fetcher`+`ParsearXMLTV` (T4).

- [ ] **Step 1 (test):** con un provider cuyo M3U declara `url-tvg` y un Fetcher/parser falsos que devuelven 2 programas, tras `sincronizarFuente` la guía de ese provider tiene 2 filas y `tvg_url` queda sellada.
